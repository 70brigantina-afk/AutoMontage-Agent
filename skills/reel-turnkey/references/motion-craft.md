# Справочник ремесла motion

Короткие числа и запреты для движения в ролике. Читай перед раскладкой движений и перед
сборкой motion-слоя. Источник чисел – код `src/motion-kit/` (`motion.js`, `captions.js`) и
`docs/MOTION-KIT.md`; если код и справочник разошлись, прав код, а справочник чинят.

Все кадровые числа даны при эталоне 25 fps и пересчитываются под fps композиции через
`ref25(n, fps)`. Секунды записаны с запятой.

## Числа движения

| Что | Значение |
|---|---|
| Вход элемента | вход маской (`mask`) – 8 кадров (0,32 с) с `EASE.out` = `bezier(0.16, 1, 0.3, 1)`; входы `fly` и `pop` – пружины, длительность задаёт пружина (`fly` `{ damping: 16, stiffness: 160, mass: 0.8 }`, `pop` `{ damping: 12, stiffness: 200, mass: 0.7 }`) |
| Выход элемента | 5 кадров (0,2 с) с `Easing.in` |
| Появление прозрачности у `pop` | 3 кадра |
| Шаг появления слов внутри фразы | 2–3 кадра (0,08–0,12 с) |
| Шаг между пунктами списка | 4–6 кадров (0,16–0,24 с) |
| Текстовый блок держится | не меньше 1,2 с и не меньше 0,3 с на каждое слово сверх четырёх |
| Субтитры | не более 4 слов и 20 знаков в куске; кусок короче 0,45 с приклеивается к следующему |
| Визуальное событие | каждые 1,5–2,2 с |
| Врезка-перекрытие | не короче 0,68 с |
| Вспышка и заметный звук | не чаще 1 раза в секунду |

## Один пик на ролик

Самый сильный приём – punch камеры, ударный звук и крупный текст одновременно – ставь ровно
один раз за ролик, на главной мысли и не в первые 2 с. Остальные акценты заметно слабее: без
punch и без ударного звука на каждом из них.

## Запреты

- Больше двух движущихся текстовых блоков одновременно.
- Текст исчезает раньше 1,2 с.
- Одно и то же движение больше трёх раз подряд.
- `bounce` и `elastic` на тексте.
- Линейная скорость (`linear`) на входе.
- Анимация каждого слова субтитров.
- Мигание одним кадром.

## Графика поверх спикера

Можно:

- `stock`, `screen` и `scene` с `cover: true`;
- карточка сбоку без пересечения с лицом, стороны чередуются.

Нельзя:

- перекрывать спикера в первые 2 с;
- закрывать лицо подписью;
- держать донорское видео дольше 3 с подряд;
- в последней трети ролика показывать лицо чаще, чем графику.

Источники правил: `docs/editing-rules.md` и `docs/MOTION-KIT.md` (гейты G1–G12 и G16).

## Переходы

Переход между сценами делает объект в кадре, а не эффект ради эффекта. Правила:

- Переход ставь только на смене мысли. Внутри одной мысли (пункты списка, шаги схемы)
  остаётся `cut`: сцены меняются встык, как раньше.
- Ставь один тип «большого» перехода на ролик: `push` или морф вставки (`origin` в motion-kit). Все
  остальные границы – `cut`, `fade` или `slide`. Два разных больших приёма в одном ролике
  спорят друг с другом.
- Презентации на HTML-in-canvas (`book-flip`, `crosswarp`, `cross-zoom`, `dreamy-zoom`,
  `dissolve`, `film-burn`, `linear-blur`, `ripple`, `swap`, `zoom-blur`, `zoom-in-out`)
  не использовать: они опираются на экспериментальный API Chromium. В ТЗ допустимы только
  пять типов из таблицы.

Переход сцены motion-reel – необязательное поле `transition: {type, frames, direction}` у сцены
ТЗ; оно описывает вход в эту сцену из предыдущей, у первой сцены его быть не может.

| Тип | Что делает | Когда |
|---|---|---|
| `cut` | жёсткая склейка (по умолчанию), полей нет | внутри мысли, по умолчанию |
| `fade` | плавное растворение, `direction` не задаётся | мягкая смена темы, пауза в речи |
| `slide` | новая сцена въезжает, `direction` | смена блока, пока тема та же |
| `wipe` | шторка, `direction` | смена блока с явной границей |
| `push` | кадры едут вместе, середина на границе, `direction` не задаётся | единственный «большой» переход ролика |

Числа (эталон 25 fps, пересчёт под fps ролика через `ref25(n, fps)`):

| Что | Значение |
|---|---|
| Длительность перехода сцены | по умолчанию 10 кадров (0,4 с), допустимо 6–15 кадров |
| Морф вставки (`origin`) | 9 кадров: карточка растёт из рамки элемента до полного кадра |
| Наезд камеры (`pushes`) | 12 кадров в центр рамки элемента, масштаб не больше `maxScale` профиля (по умолчанию 1,25) |

Как движок исполняет переход (источник – код, не угадывай):

- Содержимое новой сцены видно ровно в её `start`; предыдущая сцена тянется под переход. Если
  её клип кончился раньше, держится стоп-кадр последнего кадра, видео не продолжается.
- Переход можно ставить и после паузы между сценами: предыдущая сцена удлиняется через паузу.
- `push` идёт по центру границы: начинается на половину длины раньше `start`, середина – в
  кадре `start`.
- Переход не длиннее самой сцены и предыдущей; вход в сцену не должен накладываться на выход
  `push` в следующую. Иначе валидатор остановит ТЗ с понятной ошибкой.
- `direction` (`left`, `right`, `up`, `down`) бывает только у `slide` и `wipe`; `left` – новая
  сцена въезжает справа. Лишние поля (`direction` у `fade`/`push`, `frames` у `cut`) – ошибка.

Морф и наезд в motion-слое (подробности – `docs/MOTION-KIT.md`):

- `origin: '<id элемента>'` у вставки: карточка растёт из рамки этого элемента. Элемент-опора
  рисуется поверх вставки, поэтому заканчивай его около конца раскрытия (9 кадров), иначе он
  висит поверх уже открытой вставки.
- `pushes: [{at, target, frames?, k?}]` у камеры: наезд на элемент. Двигается только видео
  спикера, сам оверлей-элемент не масштабируется.
- Элемент, на который указывают `origin` или `target`, обязан быть виден в кадре начала
  вставки или наезда: иначе `layer check` остановит слой (гейт G16).

Критик оценивает переходы в оси `motion` по этому разделу.

## Версия Remotion

Используй только API той версии Remotion, что указана в `package-lock.json` (сейчас 4.0.536).
Перед новым API проверь его в `node_modules/remotion` этой версии. Примеры из более новой
документации не копируй. Обновлять Remotion внутри работы над роликом нельзя.
